## Server Leaderboard (`server_stats.py`, `web/server_board.py`)
- Source is the CS2 server's **HTTP log** (`logaddress_add_http`), not demos: every mode logs, the coach parser is round-based, and GOTV would need recording per map. Measured 2026-10-29: plain-text lines `MM/DD/YYYY - HH:MM:SS.mmm - <event>`, headers `X-Server-Instance-Token` (new per server start), `X-LogBytes-BeginOffset` (continues per instance, also across a new destination), `X-Game-Map`. CS2 sends the next batch only after the previous was answered.
- Each batch is appended raw to `server_logs/YYYY-MM-DD.log` (day = receive time) next to the config, prefixed `#batch <instance> <offset> <map> <received>`. Resent batches are dropped *when reading*, by **content**, not offset: after a restart on 2026-10-30 two *different* batches both had offset 0 (server.cfg runs twice at start and re-registers the receiver), and the instance token does change per start.
- **The server's clock is not trusted.** After the container was recreated from the CLI its log ran in UTC (23:13 while local was 00:13). The parser shifts each batch by receive time minus first line, rounded to 15 min. **Recreate the CS2 container via the Unraid GUI ("Apply"), not `rebuild_container` from a shell**: the CLI path does not load `var.ini` and creates the container with `TZ=` and `HOST_HOSTNAME=` empty; it also leaves a container stopped unless it is listed in `/var/lib/docker/unraid-autostart` (CS2 is, since 2026-10-30). Stats are recomputed from the raw lines on every request (cached on size+mtime) and never stored, like findings.
- `/server` and the ingest are **public** (`auth.PUBLIC_ENDPOINTS`): everyone who plays may look; the server cannot log in. The ingest is guarded by a token in the URL (`.serverlog_token` next to the config, O_EXCL like `.secret_key`, not in config.yaml). The `server.cfg` lines with the token are shown on `/server` only when logged in.
- Ranking is a **duel Elo** (each human kill = won duel, K=8, start 1000): mode-agnostic and rewards beating stronger players. Below `MIN_DUELS` (30) a player is listed as "vorlaeufig" without rank. Bots, suicides and world damage never count for Elo or K/D (bot kills have their own column); same-team kills *do* count, because in FFA deathmatch everyone shares a team and the log does not say which mode is running.
- "Bestenliste zuruecksetzen" (`/server/reset`, login only) **moves** the raw logs to `server_logs/archiv/<timestamp>/` instead of deleting them; `read_logs()` reads the top level only.
- **In-game commands** (`server_live.py`): `!top`, `!rank`/`!myrank`, `!session` (last 6 h), `!nemesis`, `!vs <name>`, `!help`. The coach sees chat lines in the log within a second and answers with `say` over RCON (`server_rcon_host/port/password` in config.yaml) - no Metamod/CounterStrikeSharp, which break on CS2 updates. Everything sent goes through `_safe()`: player names end up inside an RCON command, so `"`, `;` and control characters must never pass. Per-player cooldown 3 s.
- Discord (`server_webhook`, else `discord_webhook`): a summary per finished game ("Game Over", >= 5 human kills) and "Spieler der Woche" (best Elo among players with >= 30 duels in the previous calendar week) with the first batch of a new week - no scheduler. Each message is sent once via an O_EXCL marker in `server_logs/.posted/`; a failed post removes its marker and is retried with the next batch.
- `server.cfg` (persisted on the cache mount) sets `hostname`, logging, the log receiver and `rcon_password`; verified 2026-10-30 that it runs on server start.
- Point CS2 at the coach's **LAN** address (`http://192.168.188.71:5001/...`), not the public URL - Cloudflare's bot protection already blocked GitHub's checks.

## Uebungsmodus (`practice_mode.py`, plugin 1.29.0, 2026-11-21)
- `!uebung` / `!uebung aus`: reads the current cvars over RCON (`name = value`, booleans come back as `true`/`false`), sets `SETUP` (sv_cheats 1, round never ends, 60 min, buy anywhere, respawn, infinite ammo), restores exactly the saved values on off - aim_multigame sets its own, defaults would be wrong. Owner, or anyone alone on the server (sv_cheats = noclip for all). Plugin `coach_practice 0|1`: TakesDamage off + health 100 + money 16000 every 32 ticks; resets itself on OnMapStart. `coach_keys <uid> 0|1` / `!tasten`: W/A/S/D, JUMP, DUCK, SHIFT, L/R/L+R in the center HUD every tick (dead/spectating: the observed player's buttons). Shares the center with menus/HUD (menu wins) and QuakeSounds center messages.
- `!rethrow`/`!nochmal`: Coach sendet `sv_rethrow_last_grenade` per RCON (aus der Client-Konsole auf dem dedizierten Server wirkungslos); letzte Granate des Servers, nicht pro Spieler. `!zurueck`: `coach_nade_last` -> `coach_tp` an Wurfpunkt + Blick (nur gelandete Wuerfe). Beides nur bei aktivem Uebungsmodus.

## Aim values of all players on the server (`server_aim.py`, 2026-11-12)
- `/server` (public) shows per human player crosshair placement (median over *all* single kills, from 10 kills), counter-strafing, accuracy, HS, K/D - from **GOTV demos** parsed with `parse_demo` (all 10 players in one pass, 13.7 s per match demo), not from the plugin. Only the values stay (`server_aim/<demo>.json`), the demo is deleted.
- The coach sends `tv_record coach_<time>` over RCON when a batch has human activity (not during training, at most every 60 s) and `tv_stoprecord` when the last human leaves; a map change ends the recording too. `docker/unraid/server-demos.sh` (host cron `*/2`) moves `coach_*.dem` unchanged for 5 min from the CS2 game dir to `server_demos/` next to the config; `/server` starts the analysis in a thread (O_EXCL lock).
- **GOTV in CS2** (measured): every map load resets `tv_enable`, and server.cfg sets it again only after GOTV init -> "SourceTV not active". `tv_enable_dynamic 1` + toggling `tv_enable 0/1` starts it at once - `maybe_record` does that on "not active". A hibernating server (no humans) does not start it. The GOTV bot "Coach-Aufnahme" is a BOT in `status` and A2S (waechter counts 0 humans) and joins Spectator - the training only counts bots that join CT/T.
- **CS2 update 2026-11-11 (build 14197) broke demoparser2 < 0.42.2** (upstream #374, fixed in 0.42.2, released 2026-11-12 14:44): 0.42.1 raised `IllegalPathOp`, 0.42.0 on the server raised `EntityNotFound` for the two matchmaking demos of 2026-11-12 evening (yet parsed a 12.11. afternoon demo locally - not every demo is hit). Upgraded the server container to 0.42.2 by hand on 2026-11-13 and re-ran `batch --only-outdated`; `requirements.txt` now requires `>=0.42.2`. Inside the container the CLI is `python -m cs2_coach`, there is no `cs2-coach` script. **A `pip install` in the container is lost on recreate** - and the entrypoint only installs *missing* packages, not too-old ones; the version bump arrives via `docker-update.sh` (requirements changed) or an image rebuild. Failed server demos are retried once the installed demoparser2 version changes (`<demo>.failed` holds the version).
