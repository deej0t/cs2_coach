# Duell-Training auf dem Server + Plugin
← [[CLAUDE]] · Detailnotiz, wird nur bei Bedarf gelesen.

## Duel Training on the Server (`training_server.py`)
- `!training <map>` (owner only: `steam_id` + `training_admins`, server must have no other human) replays every death from the exports (`kill_positions`, t="d", gun kills >= 150 units): at each `Round_Start` you are put at your death position, a bot with the killer's weapon at the killer's position; the bot stays frozen for a start delay, then its own AI pushes. `!skip` (`endround`), `!leichter`/`!schwerer`, `!stop`. Every 5 duels the level adapts (4+ wins: shorter delay, then `bot_difficulty` up; <= 1: easier). Maps only from `training_maps` (Premier/FACEIT pool, plus de_cache at the player's request) - exports do not record whether a match was Premier.
- **Scenarios with several enemies** (`training_scenarios.py`, `!training <map> situation|retake|halten`, menu: map -> mode): *situation* = your death with every enemy within 2500 units (killer first), *retake* = 1 s after a plant while you are an alive CT (all Ts), *halten* = CT round, 5 s before your first contact, >= 2 Ts near. Every enemy starts where he stood and walks his real path - nothing invented, so whether they come one after another or together is how it was. bot_quota = largest scenario (max 5); surplus bots get `coach_slay` (plugin 1.6.0); a round is won when all *active* bots are dead. Scenarios live in `.training_items.json` (up to ~1 MB), not in the state file that is rewritten on every log batch. Scans are cached per demo (`scan-v2-lead<n>`; v2 added `mates`); first run on Mirage: situation 21.6 s, retake 92.5 s for 20 (retakes are rare) -> at most `MAX_NEW_SCANS` (15) new demos per start. No bomb on the server: bots cannot plant via console.
- **Teleport goes through our own server plugin** (`server_plugin/CoachTeleport`, CounterStrikeSharp on Metamod:Source 2): `coach_tp <userid> x y z pitch yaw` calls `Teleport()` with view angles; `coach_tp_version` lets the coach refuse `!training` when the plugin is not loaded. Userids come straight from the log (`dj<0>`, `Orlow<3><BOT>`), so there is no entity mapping. **Why a plugin** (measured 2026-10-30): no console command moved a *human* - with `ent_setpos` on his pawn dj still stood at T spawn 7 s into the round; `ent_setpos` only moved bots while frozen in freeze time; `setpos_player` moved nobody. Several live probes failed for setup reasons (no freeze time in warmup; `mp_restartgame` fires two `Round_Start`s) - measure in a natural round, read the position from the bot's `attacked` line or `bot_kill` (logs `committed suicide` with position; `ent_fire <idx> SetHealth 0` logs nothing).
